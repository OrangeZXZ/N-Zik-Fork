# Changelog Convention (N-Zik)

To maintain a clean and consistent project history, it is recommended to use the following standard keywords at the beginning of each line in `Done.txt` or fastlane changelog file:

## Standard Keywords:

- **Added:**
  For any new feature, screen, or capability added to the application.
  *Example: Added: New option to change the visualizer line thickness.*

- **Changed:**
  For changes in behavior, design, or logic of an existing feature.
  *Example: Changed: Default thumbnail roundness changed from 12 to 20.*

- **Improved:**
  For minor user interface (UI), user experience (UX), or performance enhancements that are neither entirely new features nor outright bug fixes.
  *Example: Improved: Visualizer buttons now dynamically squeeze if the thumbnail shape is round.*

- **Fixed:**
  For any bug fixes or crash resolutions.
  *Example: Fixed: Line thickness setting now correctly applies in real-time without restarting the view.*

- **Refactor:**
  For internal code changes that do not alter existing external behavior or functionality, but improve the code structure, readability, or maintainability.
  *Example: Refactor: Extracted visualizer control buttons into a separate composable function.*

- **Removed:**
  For features or options that have been intentionally taken out of the application.
  *Example: Removed: The legacy video player component is no longer available.*

- **Deprecated:**
  For features that are still present but are marked to be removed in a future update.
  *Example: Deprecated: The old visualizer style is deprecated and will be removed in v2.0.*

- **Other:**
  For miscellaneous updates, documentation changes, or dependency bumps that don't neatly fit into the above categories.
  *Example: Other: Updated Gradle plugins to the latest stable versions.*
