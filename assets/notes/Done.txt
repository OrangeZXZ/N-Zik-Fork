  - On device switch, playback is paused, volume is polled every 250ms for 3 seconds to let hardware route settle, then playback resumes after ~1s

Fixed:
- fix(database): optimize redundant upserts when playing songs
  - Avoided rewriting `Song`, `Artist`, and `Album` entities to the database continuously if their final state matches the existing database record.
  - This prevents the "24/7 overwrite" behavior when landing on tracks, drastically reducing unnecessary database I/O overhead.
- fix(player): skip redundant parallel album fetches on playback
  - Added a `lastFetch` column to the `Album` database table via a Migration (v32 to v33).
  - `StreamResolver` now permanently skips fetching an album if it was already fetched within the last 30 jours, drastically reducing API spam across app restarts.
- feat(player): intelligent background catch-up for artists
  - Added a `lastFetch` column to the `Artist` database table via a Migration (v33 to v34).
  - `StreamResolver` will now intelligently fetch a missing or outdated (older than 30 jours) artist profile in the background during playback, ensuring profile pictures are always complete and up-to-date.
  - Manual user modifications to Artist and Album metadata are strictly protected from being overwritten during background fetches via `PropUtils.retainIfModified`.
  - Conducted a comprehensive audit of all Artist and Album upserts across the codebase (`Database.kt`, `StreamResolver.kt`, `UpdateYoutubeEntity.kt`, `HomeSyncService.kt`, `SyncYTMusicUtils.kt`) and fixed all occurrences where network fetches could bypass `PropUtils` and overwrite user customizations.
- fix(player): volume slider not updating on manual hardware device switch
  - Added `isUserDragging` guard to prevent `VOLUME_CHANGED_ACTION` from fighting with user slider input
  - 3-second polling loop after device switch catches delayed OS volume adjustments
